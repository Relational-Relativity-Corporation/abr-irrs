# eval/

This directory holds the declaration evaluation record and Origin authorization for each build.

## Process

### 1. Evaluator runs (automatic — every push/PR)

The evaluator reads a declaration from a JSON file and produces `eval/record.json`. The declaration identifies every input value (its classification, source identity, acquisition method, and provenance), verifies the Regional M prerequisite, and traces the authorized mapping chain.

```sh
cargo run -p irrs-eval -- evaluate \
  --declaration examples/datafeel-circadian/eval/declaration.json \
  --output eval/record.json
```

`irrs-eval` is domain-independent. It contains no application-specific constants or logic. The declaration file is the only domain-specific input.

On the first run with no authorization file, the evaluator exits with code 2 (passed; awaiting authorization). The build job does not execute. The record is uploaded as a CI artifact.

### 2. Origin reviews the record

Download `evaluation-record` from the CI artifacts for the relevant commit. Read:

- **input_inventory** — confirm every value is classified correctly.
  - `PrimaryObservable`: must come from an identified observational acquisition process.
  - `DeclaredParameter`: a declared constant or configuration value.
  - `DerivedValue`: produced by the gate, not submitted by the Generator.
  - `SimulatedInput`: generated within a declared simulation or test fixture.
  - `AbstractInput`: conceptual or stipulated value without observational basis.
- **provenance_summary** — note how many inputs are declared vs. verified.
  Declared provenance is asserted by the submitter; verified provenance is supported by evidence. An initial declaration where all provenance is declared is acceptable; Origin notes which inputs would benefit from independent evidence.
- **regional_prerequisite** — confirm all four fields are declared and the interior-locus condition is verified.
- **mapping_chain** — confirm the executor is always "AdmissionGate (not Generator)".
- **evaluation_notes** — any inconsistencies or observations the evaluator flagged.
- **status** — must be `passed_awaiting_authorization` before you authorize.

### 3. Origin commits authorization

Create `eval/authorization.json` with the following content:

```json
{
  "record_id": "<copy from eval/record.json>",
  "authorized_by": "<your name>",
  "authorized_at": "<YYYY-MM-DD>",
  "statement": "<your explicit statement of what you reviewed and what you authorize>"
}
```

Commit this file to the repository. The `record_id` must match the record exactly — the evaluator will not apply a mismatched authorization.

### 4. Build proceeds

On the next push, the evaluator finds `eval/authorization.json`, verifies the `record_id` matches, sets `status: authorized`, and exits 0. The build job runs.

## What lives here

| File | Committed? | Written by |
|------|-----------|-----------|
| `authorization.json` | Yes — committed by Origin | Origin |
| `record.json` | No — generated by CI | `irrs-eval` binary |
| `schemas/declaration.schema.json` | Yes | IRRS |

`record.json` is in `.gitignore`. It is produced fresh on every CI run and uploaded as a workflow artifact, not stored in the repo.

## Declaration files

Declaration files live alongside their example:

```
examples/datafeel-circadian/eval/declaration.json
```

The declaration format is documented in `eval/schemas/declaration.schema.json`.

## When the declaration changes

If the topology ID, domain, or version changes, the `record_id` changes. The existing `authorization.json` will no longer match. The evaluator will warn, revert to `passed_awaiting_authorization`, and hold the build. Origin must review and re-authorize.

If the declaration file changes but the version does not, the `record_id` is unchanged. Origin should still review the evaluation record for the new push to confirm the changes are acceptable.

## Adding a new problem space

1. Create `examples/<domain>/eval/declaration.json` following the schema in `eval/schemas/declaration.schema.json`
2. Run `cargo run -p irrs-eval -- evaluate --declaration examples/<domain>/eval/declaration.json --output eval/record.json`
3. Review `eval/record.json`
4. Commit `eval/authorization.json` if it passes

No changes to `irrs-eval` are required.
